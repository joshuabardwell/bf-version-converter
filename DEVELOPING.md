# Developing bf-version-converter

The web app: paste Betaflight CLI text, get it converted to another firmware version, side by side, with
every change explained. A static site (GitHub Pages); the conversion runs in the browser.

## Run, build, test

```
npm install
npm run dev          # http://localhost:5173/bf-version-converter/
npm run build        # type-check + production build
npm run preview      # serve the production build
```

- **Windows PowerShell:** if `npm` is blocked by the script policy, use `npm.cmd` (or run
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once).
- **Build and cache locations:** locally, Vite's dependency cache and the build output go to the OS temp
  directory (`bf-version-converter-vite`, `bf-version-converter-dist`), not into the project: inside a
  synced or antivirus-scanned folder, Vite's renames fail with EBUSY/EPERM. CI (`CI` set) builds `dist/`.
- **Browser parity test:** `PARITY_CASES=<cases.json> npm run test:browser` builds nothing; build first.
  It serves the build, loads the engine in headless Chromium, pastes each case and requires the Copy
  button's text to equal the case's `expected` text exactly. The cases are generated by the map
  pipeline (they contain simulator output), not kept here. First run: `npx playwright install chromium`.

## How it fits together

```
public/engine/            GENERATED by the map pipeline (`bfmap bundle`) - do not edit here
  bfmap-engine.zip          the converter: Python, standard library only
  data/<A>_to_<B>.json      one version pair: map, settings, command tables, the explanations' text
  manifest.json             series (oldest first), pairs, hashes, maps date
public/cli-dump-all.webp  helper image (the CLI tab after `dump all`)
src/
  engine/engine.worker.ts   Pyodide (pinned v314.0.7 from jsDelivr) + the bundle, in a web worker
  engine/useEngine.ts       React hook: starts the worker on page load, converts (debounced 250 ms)
  engine/protocol.ts        types of the engine's response (rows, outcomes, detection)
  lib/display.ts            engine rows -> aligned side-by-side lines, folds, note rows, counts
  components/DiffView.tsx   the diff grid, folds, note rows, minimap, next-attention
  components/parts.tsx      helper (empty state), paste box, "How it works"
  App.tsx                   page state: versions, edge states, edit mode, copy/download, banner
  styles.css                design tokens (Nocturne + attention amber) and all styles
scripts/browser-parity.mjs
.github/workflows/pages.yml  build + deploy to GitHub Pages on push to main
```

**Data flow.** The worker loads Pyodide, unpacks `bfmap-engine.zip` into `/engine`, parses the
manifest and every pair once, and exposes one call: `app_convert(request)`, JSON in and out.

- Request: `{text, src_series (null = from the header), dst_series}`.
- Response: `status` (`converted`, `same`, `need_source`, `unsupported`, `empty`, `not_cli`),
  `detect` (version, platform, board, kind), and when converted: `text` (exactly what Copy copies,
  header included), `attention_lines`, and `rows`. Each row is one line of the pasted text (or a line the
  converter adds): `src_line`, `outcome`, `attention`, `lines` (what it writes), `notes` (plain-language
  note and detail), `prs`, `group` (a merge), `suggest` (for an unrecognized name).
- The app never decides conversion: outcomes, attention, wording and the converted text all come from
  the engine. The UI decides presentation only.

## Rules

- **Never edit `public/engine/`.** Conversion changes are made in the map pipeline, tested against
  Betaflight's simulator (SITL), and re-bundled. The browser parity test proves the bundle and the UI
  reproduce the engine exactly.
- **Nothing copied from Betaflight's source goes into this repository.** The bundle carries names,
  values, our own rules and explanations, and PR numbers/titles only.
- The site stores nothing and sends the pasted text nowhere: keep it that way (no analytics, no
  storage of configurations).
- Explanations shown to pilots never name a Configurator tab; they say how to set a value in the CLI.
  The tool is called the "Betaflight Configurator App".

## Design

Dark, compact UI in Inter (JetBrains Mono for CLI text), outlined accent buttons, 8 px radii. Amber is
reserved for lines that need the pilot's attention. Unchanged lines are quiet, changed lines a light
accent tint, attention lines amber. Mobile: v1 shows a "works best on a bigger screen" note.
